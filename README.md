# ReVerfyx Steam Hours

Своя небольшая консольная программа для учёта времени в играх Steam на Ubuntu VPS через SSH. Не форк ASF. Подключение к протоколу Steam реализовано открытой библиотекой [steam-user](https://github.com/DoctorMcKay/node-steam-user).

## Возможности

- Dota 2 по умолчанию (AppID `570`), выбор до 32 игр.
- Настройка по-русски, скрытый ввод пароля, Steam Guard из почты/приложения.
- Пароль не записывается на диск. Для следующих входов сохраняется токен сессии с правами `600`.
- Восстановление соединения средствами steam-user, пауза при игре с другого устройства.
- Автозапуск через systemd, журнал, защита от двух одновременно запущенных экземпляров.
- Нет веб-панели, открытых входящих портов, торговых функций или отправки данных автору программы.

Около одного реального часа даёт один час в каждой выбранной игре, если Steam принимает статус. Это не ускоритель времени, не реальные матчи и не прогресс в Dota. Игры должны принадлежать аккаунту, включая бесплатные; добавь Dota в библиотеку заранее. Программа не проверяет лицензии и не обещает начисление часов: проверяй результат в Steam. Локальная оценка отражает время отправленного статуса, а не подтверждённые Steam часы. Условия Steam и поведение сервиса могут меняться; гарантий отсутствия ограничений аккаунта нет.

## Установка с телефона через Termius

Ubuntu 22.04/24.04, x64 или ARM64. Нужны доступ к Steam, GitHub, npm и права sudo. GPU и установка игр не нужны. Команды выполняются **на VPS**.

```bash
sudo apt update
sudo apt install -y git
git clone https://github.com/ReVerfyx/Steam.git
cd Steam
bash scripts/install.sh
npm run setup
npm run login
bash scripts/service.sh install
```

В настройке введи логин для входа в Steam (не отображаемый ник), затем AppID игр через запятую. Enter без списка выбирает Dota 2. При `login` введи пароль и требуемый код Steam Guard. Дождись сообщения «Сессия сохранена». Пароль при вводе не виден. После установки службы SSH можно закрыть, после перезагрузки VPS программа запустится снова.

`install.sh` устанавливает Node.js 24 из подписанного репозитория NodeSource, если Node.js 22+ ещё нет, затем зависимости из lock-файла. Служба работает от пользователя, выполнившего `service.sh install`; для отдельного пользователя сначала клонируй проект и настрой вход под ним. Не запускай этот скрипт через `sudo`, если хочешь службу от обычного пользователя: скрипт сам запросит sudo для systemd.

## Управление

```bash
bash scripts/service.sh status
bash scripts/service.sh logs
bash scripts/service.sh stop
bash scripts/service.sh start
bash scripts/service.sh restart
npm run status
```

Ctrl+C при просмотре журнала закрывает просмотр, а не службу. `npm run status` показывает последний снимок; актуальное состояние службы проверяй командой `status` выше.

Запуск вручную для проверки (без установленной/работающей службы): `npm start`. Остановка — Ctrl+C. Для постоянной работы используй службу, не запускай второй экземпляр в tmux.

## Добавить вторую игру

Найди страницу игры в магазине: в `https://store.steampowered.com/app/570/Dota_2/` число `570` — AppID.

```bash
bash scripts/service.sh stop
npm run setup
bash scripts/service.sh start
```

Введи прежний логин и новый список, например `570,730` (Dota 2 и CS2). Для другого аккаунта после setup также выполни `npm run login`.

## Повторный вход и ошибки

Если токен истёк/отозван или Steam требует авторизацию:

```bash
bash scripts/service.sh stop
npm run login
sudo systemctl reset-failed steam-hours
bash scripts/service.sh start
```

При неверном Steam Guard программа ждёт 30 секунд, затем просит свежий код. При ошибках авторизации служба останавливается с кодом 78, чтобы не повторять неверный вход бесконечно. После остальных фатальных ошибок systemd повторяет запуск через минуту, максимум пять запусков за десять минут. Если Steam недоступен, проверь журнал и исходящие соединения VPS. Успех установки не означает успешную авторизацию в Steam.

`Программа уже запущена` — останови службу или процесс в другом SSH/tmux. После аварийного завершения блокировка с несуществующим PID очищается автоматически. Если осталась повреждённая блокировка, сначала проверь `pgrep -af 'src/cli.js'` и состояние службы; только при отсутствии работающего экземпляра удали `data/instance.lock`.

## Сессия и приватность

`config.json` и `data/` исключены из Git. Токен в `data/session.json` даёт доступ к аккаунту: не отправляй папку другим людям и не публикуй её. Права файлов защищают от других обычных пользователей VPS, но не от root/администратора хостинга. Для отзыва доступа останови службу и отзови устройство через настройки безопасности Steam.

## Структура

```text
src/cli.js                 CLI, авторизация, Steam Guard, сессия, журнал
src/core.js                проверка AppID, состояния, приватная запись JSON
test/core.test.js          проверки без доступа к аккаунту
scripts/install.sh         Node.js и зависимости
scripts/service.sh         автозапуск и управление systemd
config.example.json        образец настройки
package.json               команды и зависимость
package-lock.json          зафиксированные зависимости
.github/workflows/check.yml автоматические проверки
config.json                создаётся локально, не публикуется
data/                      создаётся локально, не публикуется
```

Проверки: `npm run check && npm test`. CI проверяет синтаксис и логику без аккаунта Steam. Реальную авторизацию и начисление времени можно проверить только после твоего входа на VPS. Проект не связан с Valve.

## Несколько аккаунтов и бесплатные игры

Существующие `config.json` и `data/session.json` автоматически используются как профиль **main**. Другие аккаунты изолированы в `accounts/<имя>/config.json` и `accounts/<имя>/data/`. Пароли не сохраняются. Каждый аккаунт проходит Steam Guard отдельно. Один Steam-логин нельзя добавить дважды.

Обновление установленной версии:

```bash
cd ~/Steam
sudo systemctl stop steam-hours
git pull --ff-only
npm ci --omit=dev --ignore-scripts --no-audit --no-fund
npm run free-exclude -- main
sudo systemctl start steam-hours
```

Команда `free-exclude -- main` навсегда исключает текущий основной профиль из автоматического получения игр, включая команду для всех. Уже выбранные игры для часов сохраняются. Кроме этого, логин или имя профиля **ReVerfyx** автоматически исключены независимо от регистра букв. Если ReVerfyx — только отображаемый ник, используй `free-exclude` с именем соответствующего профиля: ник Steam не является логином и не проверяется.

Добавить второй аккаунт:

```bash
cd ~/Steam
npm run setup -- acc2
npm run login -- acc2
sudo systemctl restart steam-hours
```

В setup Enter на выборе игр копирует текущий список основного аккаунта. Убедись, что выбранные игры доступны второму аккаунту. Для третьего повтори с `acc3`. Менеджер запускает готовые профили с промежутком 30 секунд. Аккаунты без сохранённой сессии не запускаются; смотри `npm run accounts`. После изменения списка профилей перезапусти службу. Для повторного входа существующего работающего аккаунта сначала останови службу.

```bash
npm run accounts
npm run status -- acc2
sudo journalctl -u steam-hours -f
```

### Автоматическое получение бесплатных лицензий

```bash
npm run free -- all
```

Команда читает публичный бесплатный каталог Steam с пагинацией и включает очередь для всех существующих профилей, кроме исключённых. Держи SSH открытым до сообщения о завершении сборки каталога; сбор может занять десятки минут. При обрыве повтори команду — промежуточные страницы сохранены. Готовый каталог кэшируется на сутки. Новые профили, добавленные после этой команды, включаются отдельно.

Получение лицензий затем выполняется в фоне работающей службой: **один запрос раз в 90 секунд суммарно на все аккаунты**, по очереди. Перезапуск не сбрасывает задержку. Это до 40 попыток за час на всю установку, а не на каждый аккаунт. Большой каталог займёт дни или недели. Это консервативный темп, а не гарантия отсутствия ограничений Steam.

```bash
npm run free -- acc2
npm run free-off -- all
npm run free-exclude -- acc2
```

- `free` включает получение для выбранного профиля; `free-off` выключает. Перезапуск службы для этих флагов не нужен.
- `free-exclude` защищает профиль от последующего `free all`. Отмена пользовательского исключения — удалить `freeExcluded` из его config.json. Исключение ReVerfyx действует независимо от флага.
- Используется только `requestFreeLicense`: платные покупки, списание средств, обход региона и ограничений не выполняются.
- Поддерживаются доступные **free-on-demand** лицензии. Все игры во всём Steam гарантировать нельзя: каталог зависит от региона/видимости, некоторые игры недоступны, временные акции «забрать навсегда» этим методом не поддерживаются.
- Spacewar (`480`) исключён из бесплатной очереди.
- Полученные игры **не добавляются автоматически в список фарма**. Список `games` остаётся под твоим контролем (до 32 одновременно). Получение библиотеки и учёт часов — отдельные функции.
- При RateLimitExceeded/LimitExceeded очередь лицензий всех аккаунтов останавливается, состояние сохраняется. После паузы `free` разрешает возобновление, но сохранённая задержка минимум час остаётся. При RateLimitExceeded на входе менеджер завершает всю службу с кодом 78, без автоматического цикла повторных входов.
- Завершившийся с ошибкой отдельный профиль не перезапускается в цикле. Другие продолжают работу; после исправления ошибки перезапусти службу вручную.
- Каталог: `data/free-catalog.json`. Прогресс: `data/free-progress.json` или `accounts/<имя>/data/free-progress.json`. Эти файлы не публикуются. Результат `no-new-license` не считается доказательством новой покупки или владения.

Требования по памяти увеличиваются с числом аккаунтов: каждый профиль — отдельный процесс Node.js. На VPS с 2 ГБ ОЗУ начинай с двух-трёх и проверяй `free -h`.

Steam Subscriber Agreement запрещает продажу/передачу аккаунтов без специального разрешения Valve: https://store.steampowered.com/subscriber_agreement/#1 . Проект не делает такую продажу разрешённой и не гарантирует заработок. Накрученные часы не являются реальным игровым опытом.

Новые файлы: `src/profiles.js` — изоляция аккаунтов и исключения; `src/supervisor.js` — процессы и общая очередь; `src/free-games.js` — каталог и лицензии; `test/multi.test.js` — проверки профилей, очереди и остановки процессов. Существующий `farm start/stop/restart` управляет теперь всей группой.

### Автоматический режим новых аккаунтов и таймер

`npm run setup -- acc1` (и другие профили, кроме main и исключённых)
теперь запрашивает только логин. После `npm run login -- acc1` и перезапуска
службы каталог собирается в фоне, лицензии запрашиваются постепенно.
Steam Guard по-прежнему вводится вручную при первом входе.

Для ранее добавленных дополнительных профилей:

```bash
npm run auto -- all
sudo systemctl restart steam-hours
```

`main`, ReVerfyx и `freeExcluded` не переводятся в автоматический режим.
Полученные и уже принадлежащие аккаунту игры из бесплатного каталога
автоматически выбираются для часов. Spacewar исключён. Одновременно —
до 32 игр на аккаунт; ротации нет, остальные игры НЕ фармятся.
Статус протокола не подтверждает начисление часов самим Steam.
Каталог не гарантирует все игры магазина: региональные ограничения,
недоступные лицензии и временные раздачи не обходятся.

Таймер задаёт реальный срок с момента команды, включая простои и
перезагрузки. Диапазон: 1h–2400h или 1d–100d.

```bash
npm run timer -- all 30d
npm run timer -- acc1 24h
```

`all` в команде таймера исключает основной профиль main. Явное имя профиля
задаёт таймер именно ему. По окончании прекращаются и лицензии, и часы.
Повторная команда задаёт новый срок; после завершённого таймера нужно
перезапустить службу. Таймер не обещает указанное количество игровых часов.
Без команды timer автоматической остановки нет.

### Добавление нескольких аккаунтов одной командой

```bash
npm run add -- 10
```

Последовательно настраивает acc1–acc10 и выполняет вход. Логин и пароль
вводятся в SSH; Steam Guard запрашивается только если его требует Steam.
Сохранённые сессии пропускаются (это не проверка их действительности).
После ошибки команда останавливается; повтор той же команды продолжает
с первого незавершённого профиля. Между входами пауза 30 секунд.
Другой диапазон: `npm run add -- 10 11` добавляет acc11–acc20.
Количество и номера: 1–100000. Это предел нумерации, а не гарантия
возможности одновременно запустить столько аккаунтов на VPS.
После добавления: `sudo systemctl restart steam-hours`.
